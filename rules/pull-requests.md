# Pull Request Guidelines

## Workflow defaults

- Read repository instructions, the PR template, and relevant bot configuration before reviewing or drafting.
- Default reviews to read-only. Reviewing does not authorize comments, review decisions, code changes, pushes, or merging.
- Show drafted public text before posting unless the user supplied the exact final text and explicitly asked to post it.
- Treat short follow-ups such as “go ahead” as authorization for the immediately discussed action only.
- Keep public writing concise and natural; remove repeated context, private reasoning, generic filler, and LLM-style prose.

## Formatting

- Do NOT repeat the title in the PR body (unless template requires it)
- Follow the style from user's previous PRs
- Keep it concise — match the complexity of the change
- Avoid LLM smells: no "This PR...", "This commit...", "This change...", filler words, emojis, excessive **bold**, over-explaining implementation details
